# 文档导航

文档只保存能减少后续理解和决策成本的事实。代码、测试和 Git 历史已经表达清楚的内容不再复制。

| 文档 | 职责 |
|---|---|
| [目标与边界](goals.md) | 项目方向、质量目标和暂不处理的事项 |
| [设计与工程原则](design.md) | 人—Agent 协作边界与默认技术原则 |
| [工具链事实](toolchain.md) | 已验证的本地工具、Harness 和构建输入 |
| [第三方代码](third-party.md) | 实际引入的外部源码、版本与许可 |

实现形成稳定入口、接口、不变量或限制时，在 `modules/` 按模块记录当前事实。人的真实提问或重要调试产生可复用知识时，在 `learning/` 按主题记录个人理解和证据。这两个目录只在首次需要时创建。

根目录 `README.md` 记录当前能力、运行入口和近期方向；工程演进由测试、提交和必要的设计讨论共同保存。跨 Session 确实需要临时设计文件时，先由人确认是否值得保留。

写文档时指向代码和验证命令，不复述实现；一个事实只维护一处，过时内容直接修正或删除。
