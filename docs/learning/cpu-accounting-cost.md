# CPU 资源记账与固定工作量性能测量

内核中的 CPU 时间记账（`getrusage`、进程/线程用户态与内核态时间统计）以及基于 CPU 消耗触发的间隔定时器（`ITIMER_VIRTUAL` 仅计用户态 CPU 时间，`ITIMER_PROF` 同时计用户态与内核态 CPU 时间）位于每次时钟中断、陷入切换与上下文切换的热路径上。如果记账路径存在冗余加锁或重复查询，不仅会拖慢密集系统调用，还会在多核并行计算中引发跨核缓存行乒乓。

为了在不依赖猜测的前提下精确量化记账与定时器开销，BoarOS 在 `tests/cost/accounting/` 中提供了一套**同可执行文件（ELF）、固定计算量、自动化校验**的测量执行器。内核记账实现见 [资源记账模块](../modules/kernel-accounting.md)，调度与运行队列共享状态见 [调度模块](../modules/kernel-scheduler.md)。

## 一、测量框架与两套固定工作量套件

`tests/cost/accounting/cost.c` 与驱动脚本 `tests/cost/accounting/cost.py` 使用**完全相同的用户态 ELF 二进制文件**，串行启动多个指定的待测内核进行受控对照，并严格分开记录三类不可混淆的指标：

- **墙钟时间（`wall_ns`）**：从工作开始到全部线程/进程完成的真实流逝时间；
- **累计 CPU 时间（`user_ns`、`system_ns`）**：各执行者消耗的用户态与内核态处理器时间。在多核并行场景下，多线程的累计 CPU 时间可以重叠并远大于墙钟时间，不能简单相加来解释整次运行的墙钟耗时；
- **信号递送次数（`signals`）**：验证定时器的静默、装填与周期触发语义。

### 1.1 默认套件（通用计算与数据库事务）

默认模式依次运行四项单进程固定负载，每项结束后核对确定性校验和（`check`）：

| 测例名称 | 固定工作内容 | 观测侧重 |
| :--- | :--- | :--- |
| `compute` | 2 亿次位混合算术循环 | 纯用户态计算与时钟滴答记账开销 |
| `tmpfs-small-io` | 向 tmpfs 写入并回读 10,000 次 64 字节块（共 640,000 字节） | 高频系统调用陷入与内核态时间记账 |
| `sqlite-memory` | SQLite 内存库递归公共表表达式求和（1 至 50,000） | 用户态复杂计算与内存分配 |
| `sqlite-commit` | ext4 上写入 5,000 行并执行 40 次 `PRAGMA synchronous=FULL` 事务提交及完整性检查 | 混合 I/O、持久化同步与跨进程调度 |

### 1.2 定时器与多核扩展套件（`--timer-suite`）

开启 `--timer-suite` 后，执行五项固定总工作量测试，覆盖单任务高频系统调用、单核计算、内存文件读写以及 **8 线程（`compute-threads`）** 和 **8 进程（`compute-processes`）** 并行计算。每项工作分别在五种定时器状态下轮换测量：

| 定时器模式（`--timer-modes`） | 语义说明与自动化断言 |
| :--- | :--- |
| `off` | 关闭 CPU 定时器（基线参照），断言信号递送数为 `0` |
| `virtual-armed` | 装填远期不触发的 `ITIMER_VIRTUAL`，测量“已武装但未到期”的热路径检查开销，断言信号数为 `0` |
| `prof-armed` | 装填远期不触发的 `ITIMER_PROF`，测量用户态+内核态检查开销，断言信号数为 `0` |
| `virtual-periodic` | 开启周期性 `ITIMER_VIRTUAL`（触发 `SIGVTALRM`），当有效计费 CPU 时间达到 100 ms 以上时断言必须观察到真实递送 |
| `prof-periodic` | 开启周期性 `ITIMER_PROF`（触发 `SIGPROF`），断言周期递送正常发生 |

## 二、构建与运行方式

首先构建测试程序与静态 SQLite 可执行文件，再查看执行器参数说明：

```sh
make build-accounting-cost
python3 -B tests/cost/accounting/cost.py --help
```

运行对照时需显式指定架构、至少一个待测内核标签与路径、复用的测试程序 ELF 以及全新的输出目录：

- **基础参数**：`--arch {riscv,loongarch}`、`--kernel label=path`（可多次传入以对比多个内核版本）、`--program <elf>`、`--output <new-dir>`、`--repeat <N>`（默认 5 轮）。
- **平台与套件参数**：RISC-V 必须提供 `--firmware <opensbi>`；默认套件需提供 `--sqlite <sqlite3-elf>`；定时器套件启用 `--timer-suite`，并可用 `--timer-kernel` 与 `--timer-modes` 限定需要遍历定时器状态的内核与模式集合。
- **多核与宿主绑核**：启用 `--cpus 2` 或 `--cpus 4` 时要求真实 RISC-V `USER_SMP` 内核与 `--timer-suite`。传入 `--host-vcpu-cpus`（每个客户机虚拟处理器对应一颗独立宿主核心）和 `--host-io-cpu` 后，执行器会在客户机启动前经 QEMU 监控协议（QEMU Machine Protocol，QMP）固定各虚拟处理器与 I/O 线程的宿主亲和性，减少宿主调度抖动。

### 自动化轮换与正确性验收

每一轮重复中，`timer_run_plan()` 都会循环移位各 `(kernel, mode)` 组合的执行顺序，消除宿主温升或后台波动带来的系统性偏置。每次运行均为独立启动和全新磁盘副本，结束后自动验证：

1. 每项测例的计算校验和完全匹配预期常量；
2. 多核并行测例实际覆盖了全部期望的客户机处理器掩码（`cpu_mask == (1 << cpus) - 1`）并产生了真实并发执行重叠（`overlap == 1`）；
3. 客户机正常退出（退出码 42）、内核资源完全归还，且磁盘镜像通过只读 `e2fsck -fn` 检查。

全部结果及各模式中位数写入输出目录下的 `results.json`。

## 三、正式比较口径

1. **变量严格冻结**：基线与候选内核必须复用同一份测试 ELF、同一份输入与固定总工作量，同步完成边界与退出校验完全一致。
2. **正式计时关闭诊断**：正式对比性能时必须使用关闭 `COST_DIAGNOSTICS` 的发布内核；需要拆解调用次数或锁等待占比时，另行使用诊断构建单独采样。
3. **以端到端收益定论**：宿主 CPU 频率波动、宿主抢占、QEMU 动态二进制翻译（Tiny Code Generator，TCG）代码缓存布局都会影响虚拟机墙钟时间。内部计数下降可以确认重复工作已经消除，而最终性能收益仍以同条件下多轮独立运行的中位数与完整分布为准。
