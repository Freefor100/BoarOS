# 内存管理知识

本文整理从零理解内核启动期内存管理和 RISC-V Sv39 所需的基础知识。BoarOS 当前实现的接口、约束和验证方式见 [DTB 与启动内存布局模块](../modules/dtb-memory.md) 与 [物理页分配模块](../modules/physical-pages.md)。

## RAM、物理地址、虚拟地址和页框分别是什么？

物理地址标识平台物理地址空间中的位置，其中既可能是 RAM，也可能是 ROM 或 MMIO 设备。虚拟地址是分页开启后软件使用的地址，需要由 MMU 根据页表翻译成物理地址。

页是虚拟地址空间的固定大小单位，页框是物理内存中同样大小、同样对齐的单位。口语中常把二者都称为“页”，但区分它们有助于理解：页表项描述的是虚拟页如何映射到物理页框。

若页大小为 `2^n` 字节：

- 地址低 `n` 位是页内偏移。
- 页和页框起始地址的低 `n` 位必须为零。
- 向下对齐可清除低 `n` 位；向上对齐要先加 `2^n - 1`，因此必须先检查整数溢出。

内存范围通常写成半开区间 `[base, base + size)`。半开区间的长度直接等于两端之差，相邻区间可以无重叠地拼接，也便于表达空区间。处理任何 `base + size` 前都必须检查是否超过整数上限。

## 内核怎样知道哪些 RAM 可以使用？

内核不能只根据“机器有多少内存”就使用整段 RAM。固件、内核镜像、设备树、启动栈和平台保留区都可能已经占用其中一部分。

设备树 DTB 是常见的平台描述输入。与启动内存相关的内容包括：

- `/memory` 节点的 `reg` 属性描述 RAM 区间。
- memory reservation block 描述固件预留的物理区间。
- `/reserved-memory` 的静态子节点描述操作系统不得当作普通 RAM 使用的区间。
- DTB header 的 `totalsize` 给出 DTB 自身占用长度。

DTB 使用大端编码，并用父节点的 `#address-cells` 和 `#size-cells` 决定地址与长度各由多少个 32 位 cell 组成。解析器不能把未对齐的 DTB 字节直接强制转换成宿主 C 结构，而应逐字段读取、检查边界并组合整数。

得到 RAM 和保留区后，启动期通常执行以下区间运算：

1. 检查所有区间长度和端点是否合法。
2. 把保留区裁剪到 RAM 范围内。
3. 按起始地址排序。
4. 合并重叠或相邻的保留区。
5. 从 RAM 中逐段减去保留区，得到字节粒度的可用区间。
6. 将可用区间首尾向内对齐到完整页框。

向内对齐很重要：首部不足一页和尾部不足一页的碎片不能分配，否则返回的页框会覆盖保留字节或超出 RAM。

## 物理页分配器负责什么？

物理页分配器跟踪哪些 RAM 页框空闲、哪些已经发放。它返回的是页对齐物理地址，不负责决定虚拟地址，也不自动建立页表映射。

基本接口通常包括：

- 初始化：接收已经排除保留区的物理内存范围。
- 分配：取出一个或多个空闲页框，并更新所有权状态。
- 释放：把已分配页框归还；未分配地址、非对齐地址和重复释放都属于错误。
- 查询：报告总页数、空闲页数或其他统计信息。

常见数据结构各自适用于不同阶段：

- 空闲链表：实现直接，空闲页本身可以保存链指针。
- 位图：每个页框对应一个或多个状态位，适合快速测试某页是否空闲。
- 伙伴系统：按二次幂块管理内存，支持连续多页分配和相邻空闲块合并。

无论使用哪种结构，都必须定义页框所有权、失败时状态是否变化、分配内容是否清零、并发访问如何同步。页表页也是普通物理页框，因此建立页表前必须先有可用的物理页分配机制。

## 页表怎样完成地址翻译？

多级页表把一个很大的单层数组拆成按需分配的树。虚拟地址被分成“多级虚拟页号 + 页内偏移”，每一级虚拟页号选择当前页表中的一个表项。

非叶子页表项指向下一级页表；叶子页表项给出最终物理页号和访问权限。地址翻译大致如下：

```text
根页表
  -> 用最高级虚拟页号选择表项
  -> 进入下一级页表
  -> 用下一级虚拟页号继续选择
  -> 找到叶子页表项
  -> 物理页号 + 原页内偏移 = 物理地址
```

多级结构只为实际使用的虚拟地址范围分配下级页表，避免为整个虚拟地址空间预留连续的大数组。代价是一次 TLB miss 可能需要多次内存访问，所以 CPU 使用 TLB 缓存最近的地址翻译。

页表不仅决定地址，还决定权限。内核通常至少区分可执行代码、只读数据、可写数据和栈、用户页面、内核页面以及 MMIO。错误地给数据页执行权限或给只读页写权限会削弱隔离。

## Sv39 的地址和三级页表怎样拆分？

Sv39 是 RV64 的一种分页模式。它使用 4 KiB 基页和三级页表，每个页表恰好占一个 4 KiB 页框，包含 512 个 64 位页表项。

虚拟地址拆分为：

| 位 | 名称 | 用途 |
|---|---|---|
| `63:39` | 符号扩展 | 必须全部等于 bit 38，否则地址不合法 |
| `38:30` | `VPN[2]` | 根页表索引 |
| `29:21` | `VPN[1]` | 第二级索引 |
| `20:12` | `VPN[0]` | 第三级索引 |
| `11:0` | page offset | 4 KiB 页内偏移 |

每级索引都是 9 位，因此可选择 `2^9 = 512` 个页表项。三级基页映射覆盖的虚拟地址位数为 `9 + 9 + 9 + 12 = 39`。

RV64 的 `satp` CSR 指定分页模式、地址空间标识符 ASID 和根页表的物理页号。Sv39 的 MODE 值为 8。写入根页表物理页号时不保存低 12 位，因为根页表必须按 4 KiB 对齐。

## Sv39 页表项包含哪些信息？

Sv39 页表项的低位标志包括：

| 标志 | 含义 |
|---|---|
| `V` | 表项有效 |
| `R` | 可读 |
| `W` | 可写 |
| `X` | 可执行 |
| `U` | U-mode 可访问 |
| `G` | 全局映射 |
| `A` | 已访问 |
| `D` | 已写入 |

`R/W/X` 全为零时，有效表项指向下一级页表；其中任一为一时，表项是叶子映射。`W=1` 且 `R=0` 是保留组合，不能作为合法叶子权限。

页表遍历从 `VPN[2]` 开始。若在最高级或第二级提前遇到叶子项，就形成 1 GiB 或 2 MiB 大页；大页要求物理页号中被低级索引替代的部分为零。第三级叶子项形成普通 4 KiB 映射。

`A` 和 `D` 位表示页面是否被访问或写入。具体处理方式取决于硬件实现和内核策略：硬件可能自动置位，也可能通过页错误要求软件处理。内核不能在未确认平台行为时假设二者会自动更新。

## 修改页表后为什么要处理 TLB？

TLB 缓存虚拟页到物理页框的翻译和权限。内存中的页表项改变后，TLB 里的旧结果不会自动因为普通 store 立刻消失。

RISC-V 使用 `SFENCE.VMA` 同步页表更新与后续地址翻译。它可以刷新全部地址空间，也可以按虚拟地址和 ASID 缩小范围。启用新根页表或复用旧 ASID 时，必须按照 RISC-V 特权规范安排页表写入、`satp` 更新和 `SFENCE.VMA`，避免 CPU 继续使用旧翻译。

在切换分页前还必须确认：当前代码、栈、异常入口、根页表与下级页表，以及切换后马上访问的 UART 等 MMIO 都有有效映射。任何一项缺失都可能让错误发生在新页表生效后的第一条取指或访存。

## 架构差异和板级差异有什么区别？

架构定义 CPU 的地址翻译机制，例如页表项格式、页表遍历规则、控制寄存器和 TLB 指令。平台或开发板定义物理世界的布局，例如 RAM、UART、中断控制器、时钟和固件交接方式。

同一 RISC-V 分页模式可以用于多个 RISC-V 平台，但每个平台需要映射的物理 RAM 和 MMIO 区间可能不同。不同架构即使都使用三级页表，页大小、索引位数、页表项格式、权限位和启用方式也不能据此推定相同。

16 KiB 页有 14 位页内偏移，所有页框和页表相关结构都必须满足 16 KiB 对齐；其余索引如何划分由具体架构的页表规范决定，不能把 Sv39 的 9 位三级索引直接套用到另一种架构。
