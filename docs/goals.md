# BoarOS 演进路线与待完成项

本文如实记录 BoarOS 当前的功能边界、下一阶段的多核与架构演进重点，以及真实硬件开发板的适配计划。当前已具备的能力见 [项目主页](../README.md) 与 [系统总体架构与核心设计](design.md)。

---

## 一、多核与关键数据路径持续深化

| 优化方向 | 下一阶段重点工作 | 相关子系统 |
| :--- | :--- | :--- |
| **共享地址空间细粒度并发** | 进一步缩小固定地址覆盖替换、权限降级与文件映射装页的独占锁范围；深入验证同一地址空间并发 `fork`、解除映射、文件截断与退出时的页引用和跨核 TLB 失效时序。 | [虚拟内存管理](modules/kernel-mm.md) |
| **调度与有期限等待扩展** | 在多核独立对象高并发负载下，进一步拆分带超时等待的全局期限索引与跨核通知竞争，降低唤醒后等待调度（wake-to-run）的尾延迟。 | [进程与调度](modules/kernel-scheduler.md) |
| **存储写回与网络协议并行** | 细化页缓存前台接纳、后台写回、ext4 日志提交与最终同步之间的回压协调；持续降低网络协议内存池与跨连接共享路径的争用。 | [VFS 与 ext4](modules/vfs-ext4.md) · [网络协议栈](modules/kernel-network.md) |

## 二、尚未实现的 Linux 功能缺口

对于下列尚未覆盖的接口或扩展选项，BoarOS 均遵循 Linux 约定明确返回 `ENOSYS`（未实现）或 `EOPNOTSUPP`（不支持），不伪造成功：

| 子系统领域 | 待补齐的特性清单 |
| :--- | :--- |
| **文件系统与存储** | 挂载用户身份映射（ID-mapped mounts）、同步挂载属性、延迟时间戳更新（`lazytime`）、强制卸载（`MNT_FORCE`）、叠加文件系统（OverlayFS）的多下层配置与跨层重命名、`fanotify` 文件范围预访问通知，以及 `RWF_NOWAIT` 的直接输入输出和写入。 |
| **内存与容器隔离** | 交换空间（Swap）、透明大页（Transparent Huge Pages，THP）的后台合并和文件后备、用户命名空间（User Namespace）、网络命名空间（Network Namespace）以及控制组第二版（cgroup v2）的完整资源控制器。私有匿名映射已支持按应用建议建立或合并透明大页，见[大页设计](modules/hugepages.md)。 |
| **网络与 eBPF 扩展** | IPv6 报文分片重组、组播侦听发现协议第二版（Multicast Listener Discovery version 2，MLDv2）、通过 `rtnetlink` 动态修改路由与多地址配置；eBPF 的更多挂载点（如 `kprobe`、`uprobe`、`XDP`/`TC`）以及双架构即时编译（Just-In-Time，JIT）后端。 |
| **异步 I/O 深化** | 补齐共享输入输出环的通用异步执行、提交轮询、直接输入输出完成轮询和常规套接字的多次完成。扩展独立接收队列之外的网卡与分流方式。 |

## 三、真实硬件开发板移植计划

当前内核的完整验证均在 **QEMU `virt`** 虚拟平台上完成。下一阶段将面向两款真实硬件开发板独立推进实板验收：

- **RISC-V 64**：StarFive VisionFive 2
- **LoongArch 64**：龙芯 2K1000LA

实板移植将按 **早期引导与串口输出 → 物理内存探测与多核唤醒 → 平台中断控制器与定时器 → 存储与网卡驱动 → 真实硬件掉电恢复与吞吐测量** 依次推进。虚拟机结果用于验证内核软件逻辑与并发正确性，实板的硬件时序、外设带宽与掉电一致性将以真实硬件实测为准。
